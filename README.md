## 1. Модуль 1: Введение в Node.js

ES Modules — основной формат нового кода курса. Явные `import` и `export` делают зависимости видимыми, поддерживают top-level await и согласуются с современным JavaScript.

ESM разрешает спецификаторы до выполнения и загружает граф модулей с учётом циклических зависимостей. CommonJS выполняет `require` синхронно и экспортирует значение через `module.exports`.

В контексте этого урока раздел связан с задачей: Node.js как runtime: V8 исполняет JavaScript, Node добавляет системные API, libuv организует event loop и часть фоновой работы.

Неявное смешение форматов приводит к ошибкам загрузки, неожиданному default export и различиям между локальным запуском и тестами.

## 2. Что такое Node.js?

При разборе поведения Node.js полезно разделять JavaScript-стек, очереди задач, операции операционной системы и пул libuv. Это защищает от ошибочного объяснения, будто любой асинхронный вызов автоматически создаёт отдельный JavaScript-поток.

JavaScript выполняется до ближайшей точки возврата управления. Затем runtime может обработать microtasks, перейти к следующей фазе event loop и вызвать готовые callbacks.

В контексте этого урока раздел связан с задачей: Конкурентность не равна параллельности: JavaScript обычно выполняется в одном потоке, I/O не блокирует его, а CPU-задачи требуют Worker Threads или отдельных процессов.

Главный риск — заблокировать event loop синхронной операцией или большим вычислением и тем самым задержать все подключения процесса.

## 4. Разработка API

HTTP-запрос состоит из метода, target, заголовков и необязательного тела; ответ — из статуса, заголовков и тела. Сервер должен завершить каждую ветку ровно одним ответом.

Статус и заголовки отправляются до первого фрагмента тела. После этого изменить их нельзя; ошибка во время streaming требует отдельной политики.

В контексте этого урока раздел связан с задачей: LTS против Current: для курса и production используем Node 24 LTS; Node 26 Current подходит для экспериментов.

Отсутствие лимита body, таймаутов или ограничения заголовков открывает путь к исчерпанию памяти и соединений.

## 5. Создание стриминговых приложений

Backpressure согласует скорость производителя и потребителя. Без неё быстрый источник продолжает выделять память, пока медленный приёмник не успевает записывать данные.

Высокая отметка буфера — порог для backpressure, а не гарантированный предел всей памяти процесса.

В контексте этого урока раздел связан с задачей: Где Node.js силён: API, BFF, real-time, CLI, интеграционные сервисы. Где нужна осторожность: тяжёлые вычисления в основном потоке.

Обработчик только `data` без контроля потока переводит readable в flowing mode и может ускорить источник сильнее потребителя.
