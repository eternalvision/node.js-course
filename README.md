## 1. Создание веб-клиента и углубление в архитектуру

Встроенный fetch является стандартным HTTP-клиентом для большинства интеграций. Он отклоняет Promise при сетевой ошибке, но ответы 4xx и 5xx надо проверять через `response.ok`.

AbortSignal передаётся в fetch и связывает отмену вызывающего кода с сетевой операцией. Таймаут является одной из причин отмены, а не отдельным способом обработки ошибок.

В контексте этого урока раздел связан с задачей: Встроенный `fetch` покрывает большинство HTTP-запросов без axios.

Автоматический retry POST без idempotency key способен создать дубликаты платежа, письма или записи.

## 4. Взаимодействие с Сервером

HTTP-запрос состоит из метода, target, заголовков и необязательного тела; ответ — из статуса, заголовков и тела. Сервер должен завершить каждую ветку ровно одним ответом.

Статус и заголовки отправляются до первого фрагмента тела. После этого изменить их нельзя; ошибка во время streaming требует отдельной политики.

В контексте этого урока раздел связан с задачей: Контроллер не должен знать детали HTTP-клиента: вынесите интеграцию в gateway/service.

Отсутствие лимита body, таймаутов или ограничения заголовков открывает путь к исчерпанию памяти и соединений.
