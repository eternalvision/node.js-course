## Главное объяснение

Не запоминайте отдельные методы без модели. Сначала определите, где находится граница ответственности: runtime, транспорт, бизнес-логика, хранилище или инфраструктура. Затем выберите API и явно обработайте успешный результат, ожидаемую ошибку и отмену/завершение работы.

Современный Node.js следует использовать с поддерживаемой LTS-версией, ESM для нового кода, Promise API и встроенными возможностями там, где внешняя зависимость не даёт явной пользы. Экспериментальные API отмечайте отдельно и не делайте их обязательной частью production-решения без оценки риска.

## Подробный разбор

### Router и входные данные

`Router` группирует URL одного ресурса. Path parameter идентифицирует ресурс, query меняет фильтрацию/сортировку/пагинацию, body описывает новое состояние. Эти источники следует валидировать отдельно.

### Async в Express 5

Rejected Promise или исключение из async-handler автоматически попадает в error middleware. Старые Express 4 обёртки с `.catch(next)` обычно не нужны. Ошибку callback API всё ещё передают явно через `next(error)`.

### Контракт ошибок

Ожидаемая ошибка имеет стабильный статус и безопасный текст. Удобный формат — Problem Details (`type`, `title`, `status`, `detail`, `instance`). Stack trace, SQL и внутренние имена остаются только в серверном логе.
