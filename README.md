# 1. Современный Node.js: платформа, runtime и модули

> Версия курса: 2026 · Базовая среда: **Node.js 24 LTS** · Формат модулей: **ESM**

## Зачем этот урок

После урока вы сможете: **Запустите ESM-приложение, объясните путь запроса через event loop и выберите Node.js для подходящей задачи.**

Ориентировочное время: 2–3 часа. Сначала прочитайте объяснение, затем запустите примеры и только после этого выполняйте практику.

## Перед началом

```bash
node --version
npm --version
```

Нужна Node.js 24.x. Весь код этой ветки относится к новой версии курса; минимальный пример находится в `modern-example`.

## Карта урока

- Node.js как runtime: V8 исполняет JavaScript, Node добавляет системные API, libuv организует event loop и часть фоновой работы.
- Конкурентность не равна параллельности: JavaScript обычно выполняется в одном потоке, I/O не блокирует его, а CPU-задачи требуют Worker Threads или отдельных процессов.
- ES Modules — основной формат курса: `import`, `export`, `import.meta.url`, top-level `await`. CommonJS изучаем, чтобы читать существующие проекты.
- LTS против Current: для курса и production используем Node 24 LTS; Node 26 Current подходит для экспериментов.
- Где Node.js силён: API, BFF, real-time, CLI, интеграционные сервисы. Где нужна осторожность: тяжёлые вычисления в основном потоке.

## Главное объяснение

Не запоминайте отдельные методы без модели. Сначала определите, где находится граница ответственности: runtime, транспорт, бизнес-логика, хранилище или инфраструктура. Затем выберите API и явно обработайте успешный результат, ожидаемую ошибку и отмену/завершение работы.

Современный Node.js следует использовать с поддерживаемой LTS-версией, ESM для нового кода, Promise API и встроенными возможностями там, где внешняя зависимость не даёт явной пользы. Экспериментальные API отмечайте отдельно и не делайте их обязательной частью production-решения без оценки риска.



## Практика

1. Установите Node 24, проверьте `node --version` и `npm --version`.
2. Запустите `modern-example/runtime-info.mjs` и найдите версии Node, V8 и платформу.
3. Добавьте ESM-модуль с именованным экспортом и импортируйте его.
4. Сформулируйте, почему `setTimeout` не создаёт отдельный поток JavaScript.
