## Карта урока

- Helmet и security headers
- CORS не является механизмом авторизации
- Rate limiting и ограничение body
- CSRF для cookie-auth, XSS, injection и dependency audit

## Главное объяснение

Не запоминайте отдельные методы без модели. Сначала определите, где находится граница ответственности: runtime, транспорт, бизнес-логика, хранилище или инфраструктура. Затем выберите API и явно обработайте успешный результат, ожидаемую ошибку и отмену/завершение работы.

Современный Node.js следует использовать с поддерживаемой LTS-версией, ESM для нового кода, Promise API и встроенными возможностями там, где внешняя зависимость не даёт явной пользы. Экспериментальные API отмечайте отдельно и не делайте их обязательной частью production-решения без оценки риска.

## Подробный разбор

### Модель угроз

Helmet, CORS и rate limiter решают разные задачи. Сначала определите актив, атакующего и путь атаки, затем добавьте защиту и тест. Набор middleware без объяснения создаёт ложное ощущение безопасности.

### CORS, CSRF и ввод

CORS не заменяет authentication. CSRF важен при cookie-auth; используйте SameSite и token/проверку Origin для изменяющих запросов. Ограничивайте body, валидируйте тип и длину, параметризуйте SQL и безопасно выводите HTML.
