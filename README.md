# 2.2. Асинхронность, event loop, AbortSignal и события

> Версия курса: 2026 · Базовая среда: **Node.js 24 LTS** · Формат модулей: **ESM**

После урока вы сможете: **Пишите отменяемый асинхронный код и не блокируйте event loop.**

Ориентировочное время: 3 часа. Сначала прочитайте объяснение, затем запустите примеры и только после этого выполняйте практику.

```bash
node --version

```

Нужна Node.js 24.x. Весь код этой ветки относится к новой версии курса; минимальный пример находится в `modern-example`.

## Карта урока

- Очереди event loop, microtasks и отличие `queueMicrotask`, Promise, timer и `setImmediate`.
- Promise и `async/await` — основной стиль прикладного кода; callbacks остаются частью низкоуровневых API.
- `AbortController` передаёт отмену через слои приложения; таймаут — частный случай отмены.
- `EventEmitter` полезен для событий внутри процесса, но требует политики ошибок и снятия слушателей.
- CPU-bound работу нельзя маскировать `async`: используйте Worker Threads, очередь задач или отдельный сервис.

## Главное объяснение

Не запоминайте отдельные методы без модели. Сначала определите, где находится граница ответственности: runtime, транспорт, бизнес-логика, хранилище или инфраструктура. Затем выберите API и явно обработайте успешный результат, ожидаемую ошибку и отмену/завершение работы.

Современный Node.js следует использовать с поддерживаемой LTS-версией, ESM для нового кода, Promise API и встроенными возможностями там, где внешняя зависимость не даёт явной пользы. Экспериментальные API отмечайте отдельно и не делайте их обязательной частью production-решения без оценки риска.



## Практика

1. Запустите пример и объясните порядок сообщений.
2. Отмените долгую операцию через `AbortSignal.timeout()`.
3. Создайте emitter с событиями `order:created` и `error`.
4. Измерьте задержку event loop при синхронном вычислении.
